### II. apt的基本操作

#### `apt`的基本操作（基于大模型）

以下是基于 `apt` 命令进行软件包各种常见操作的命令行示例：

##### 1. 软件包管理

**安装软件包**

```bash
# 安装单个软件包
sudo apt install 软件包名

# 安装多个软件包
sudo apt install 包名1 包名2 包名3

# 安装指定版本的软件包
sudo apt install 软件包名=版本号

# 重新安装软件包
sudo apt install --reinstall 软件包名
```

**卸载软件包**

```bash
# 仅卸载软件包（保留配置文件）
sudo apt remove 软件包名

# 卸载软件包并删除配置文件
sudo apt purge 软件包名

# 卸载软件包及其依赖（但不再需要的包）
sudo apt autoremove 软件包名

# 自动移除不再需要的依赖包
sudo apt autoremove
```

##### 2. 更新相关

**更新软件包列表**

```bash
# 更新软件包源列表
sudo apt update
```

**升级软件包**

```bash
# 升级所有已安装软件包（不删除现有包）
sudo apt upgrade

# 执行完整升级（可能删除或添加包）
sudo apt full-upgrade

# 升级指定软件包
sudo apt install 软件包名 --only-upgrade

# 执行发行版升级
sudo apt dist-upgrade
```

##### 3. 查找和查询

**搜索软件包**

```bash
# 搜索软件包（按名称和描述）
apt search 关键字

# 使用通配符搜索
apt search "关键字*"
```

**查看软件包信息**

```bash
# 显示软件包详细信息
apt show 软件包名

# 显示软件包策略信息
apt policy 软件包名

# 列出软件包内容
apt list 软件包名
```

**列出已安装包**

```bash
# 列出所有已安装的软件包
apt list --installed

# 列出可升级的软件包
apt list --upgradable

# 列出所有可用的软件包
apt list
```

##### 4. 依赖管理

**查看依赖关系**

```bash
# 显示软件包的依赖关系
apt depends 软件包名

# 显示哪些包依赖于指定包
apt rdepends 软件包名

# 检查依赖关系问题
apt check
```

##### 5. 清理操作

**清理缓存**

```bash
# 删除下载的软件包缓存（/var/cache/apt/archives）
sudo apt clean

# 删除过期的软件包缓存
sudo apt autoclean

# 自动移除不需要的依赖包
sudo apt autoremove
```

##### 6. 下载和源码

**下载操作**

```bash
# 只下载软件包（不安装）
apt download 软件包名

# 下载软件包源码
apt source 软件包名

# 构建软件包依赖
apt build-dep 软件包名
```

##### 7. 其他实用命令

**版本控制和验证**

```bash
# 显示软件包版本
apt policy 软件包名

# 验证软件包完整性
apt-cache policy 软件包名

# 显示软件包变更日志
apt changelog 软件包名
```

**常用组合命令**

```bash
# 更新源并升级系统
sudo apt update && sudo apt upgrade -y

# 清理不再需要的包并清理缓存
sudo apt autoremove && sudo apt autoclean

# 搜索并安装软件包
apt search 关键字 && sudo apt install 找到的包名
```

##### 注意事项
- 大多数 `apt` 命令需要 `sudo` 权限（特别是安装、卸载、更新操作）
- 使用 `-y` 参数可以自动确认操作
- 可以结合 `grep` 进行更精确的搜索：`apt list | grep 关键字`
- 使用 `-h` 或 `--help` 查看命令帮助：`apt install -h`

这些命令覆盖了日常使用中最常见的 APT 包管理操作。

### III. dpkg的基本操作

#### dpkg 的基本操作（基于大模型）

`dpkg` 是 Debian/Ubuntu 系统的底层包管理工具，用于直接操作 `.deb` 软件包文件。以下是常用的 `dpkg` 命令操作指南：

##### **1. 安装软件包**

```bash
# 安装本地 .deb 包
sudo dpkg -i 软件包名.deb

# 强制安装（忽略依赖问题）
sudo dpkg -i --force-depends 软件包名.deb

# 安装并覆盖已存在的配置文件
sudo dpkg -i --force-confnew 软件包名.deb
```

##### **2. 卸载软件包**

```bash
# 仅卸载软件包（保留配置文件）
sudo dpkg -r 软件包名

# 完全卸载（删除所有配置文件）
sudo dpkg -P 软件包名

# 注意：-r 和 -P 后面跟的是软件包名称，不是 .deb 文件名
```

##### **3. 查询软件包信息**

```bash
# 列出系统中所有已安装的软件包
dpkg -l

# 搜索已安装的特定软件包
dpkg -l | grep 关键词

# 显示指定软件包的详细信息
dpkg -s 软件包名

# 列出软件包安装的文件
dpkg -L 软件包名

# 查询某个文件属于哪个软件包
dpkg -S 文件路径

# 查看 .deb 包的文件列表
dpkg -c 软件包名.deb

# 查看 .deb 包的详细信息
dpkg -I 软件包名.deb
```

##### **4. 重新配置和修复**

```bash
# 重新配置已安装的软件包
sudo dpkg-reconfigure 软件包名

# 修复安装中断的软件包
sudo dpkg --configure -a

# 强制重新安装软件包
sudo dpkg -i --force-overwrite 软件包名.deb
```

##### **5. 软件包状态管理**

```bash
# 列出标记为"需要安装"的包
dpkg --get-selections > packages.txt

# 从文件恢复软件包选择状态
sudo dpkg --set-selections < packages.txt

# 清除软件包的"已安装"标记
sudo dpkg --clear-selections
```

##### **6. 处理依赖问题**

```bash
# 忽略依赖问题强制安装
sudo dpkg -i --force-depends 软件包名.deb

# 修复依赖关系（配合 apt 使用）
sudo apt-get install -f

# 查看软件包的依赖关系
dpkg -s 软件包名 | grep Depends
```

##### **7. 常用组合命令**

```bash
# 提取 .deb 包内容到指定目录
dpkg -x 软件包名.deb 目标目录/

# 提取并保留包控制信息
dpkg -e 软件包名.deb

# 比较两个软件包版本
dpkg --compare-versions 版本1 操作符 版本2
```

##### **8. 注意事项**

1. **`dpkg` 与 `apt` 的区别**：
   - `dpkg` 处理本地 `.deb` 文件，不处理依赖关系
   - `apt` 自动处理依赖并从仓库下载

2. **常用修复命令**：
   ```bash
   # 当 dpkg 操作中断时使用
   sudo dpkg --configure -a
   
   # 修复依赖问题
   sudo apt --fix-broken install
   ```

3. **查看帮助**：
   ```bash
   # 查看完整帮助
   dpkg --help
   
   # 查看特定操作帮助
   dpkg -i --help

## 扩展练习

### `apt update`命令

#### 功能

核心功能：同步软件源（Repositories）的索引

步骤：

- 读取`/etc/apt/sources.list` 文件和 `/etc/apt/sources.list.d/` 目录下的所有 `.sources` 文件
- 连接到每个软件源服务器，下载最新的软件包元数据（软件包的名称、版本号、描述、依赖关系以及校验和等信息）
- 将下载的元数据存储在本地，用于更新系统的软件包索引数据库

#### 影响的文件

读：

- `/etc/apt/sources.list`
- `/etc/apt/sources\.list\.d/[a-zA-Z0-9_-]+\.source` 

读写：

- `/var/lib/apt/lists/*`

![image-20260320012106733](https://free.picui.cn/free/2026/03/20/69bc302dcc712.png)

#### 锁定操作

当运行任何会改变软件包状态的命令，apt都会尝试获取一个"锁"。如果另一个进程已经持有了这个锁，你的新命令就会等待，直到前一个进程完成并释放锁再执行。

#### 锁定的实现

通过锁文件（路径：`/var/lib/dpkg/lock`）实现的

当一个apt进程启动时，它会尝试在这些文件上创建一个排他锁（也称为写锁）。创建成功，则继续执行；创建失败（文件已被其他进程锁定），则等待。
